# Nightly Cron Setup

## A Nightly Job for a Hub

```bash
# crontab -e
0 2 * * * cd /path/to/hub && projectman sync && projectman audit --all && projectman commit
```

Each verb does one thing, and none of them reaches into a repo it does not own
beyond re-mounting a store:

- **`projectman sync`** — fast-forward pulls every checked-out submodule
  (skipping a dirty or diverged one with a note), then re-attaches any
  registered project whose `projects/{name}/.project` worktree has gone missing.
  Run it first so the audit reads current, mounted stores.
- **`projectman audit --all`** — runs the audit checks against every *attached*
  subproject store in turn and writes each one's `DRIFT.md` in its own store. An
  unattached subproject is named and skipped, with the hint for fixing it, so
  "audited everything" stays true. Plain `projectman audit`, with no `--all`,
  audits the hub's own store.
- **`projectman commit`** — commits the hub's own pending `.project/` changes,
  and nothing else.

## Which Store Gets Committed

`projectman commit` acts on exactly one store, named by `--prefix`:

| Invocation | What it commits |
|---|---|
| `projectman commit` | The hub's own `.project/` files, on the branch owning the hub store |
| `projectman commit --prefix API` | Only that subproject's store, inside that subproject's own repo, on its `projectman` branch |

There is no hub-wide commit. A nightly job that wants every project covered
loops over the prefixes:

```bash
for p in API WEB; do projectman commit --prefix "$p"; done
```

`projectman push` follows the same rule — one store's branch per invocation —
so a job that publishes as well as commits loops the same way. See
[git-workflow.md](git-workflow.md).

## What the Job Leaves Behind

- Every submodule fast-forwarded, and every store mounted
- A rebuilt `index.yaml` and the derived markdown indexes in the store
  `projectman commit` acted on — commit rebuilds them immediately before
  staging, so the commit carries an index matching the item files in it
- A refreshed `DRIFT.md` per audited store
- One commit per store that had pending PM changes

The hub's dashboards are **not** regenerated by any of these commands — see
[dashboards.md](dashboards.md) for how to generate them.
